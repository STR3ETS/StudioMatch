# StudioMatch

Nederlandse marktplaats waar artiesten opname- en mix/master-studio's vinden, boeken en betalen, en studio-eigenaren (verhuurders) uitbetaald krijgen via Stripe Connect. "Every sound deserves a studio." Klant: StudioMatch VOF; gebouwd door Eazyonline.

**Leidende stukken:**
- [studiomatch-scope.md](studiomatch-scope.md): functionele scope (§2), niet in scope (§3), beslispunten 1 t/m 17 (§4), aannames, aanleveringen en risico's. Bij twijfel "hoort dit erbij?" beslissen de scope-principes.
- De feedback-PDF's in de root zijn de feedbackrondes van de klant, in volgorde: MVP P1.0, P2.1, P3.0, Pilot V1, Pilot V2 (nieuwste). Elke ronde heeft een eigen testbestand (`FeedbackFixesTest`, `FeedbackP3Test`, `FeedbackPilotTest`); nieuwe feedback krijgt er ook een.
- [README.md](README.md): status, testaccounts, wat nog op de klant wacht.

## Scope-principes (tiebreaker)

1. Eén vloeiende boekingsflow gaat vóór veel functies.
2. Edge cases via de admin (handmatig vangnet), niet via extra code.
3. Stripe Connect is de financiële ruggengraat: geen eigen KYC, IBAN-check of uitbetalingsengine.
4. Mobiel is leidend, niet "ook".
5. Alles wat niet nodig is voor `zoeken → boeken → betalen → uitbetalen` is fase 2. Enige uitzondering: "Meld een probleem" met payout-hold.

## Domein

- **Rollen (`UserRole`):** `artiest`, `verhuurder`, `admin`. Routes per rol met middleware `role:...` ([EnsureUserHasRole](app/Http/Middleware/EnsureUserHasRole.php)); een admin mag overal bij, een verkeerde rol wordt naar het eigen dashboard gestuurd. Controllers per rol in `Http/Controllers/{Artist,Host,Admin}`.
- **Studio → ruimtes:** een verhuurder (`HostProfile`) heeft studio's (`Studio`, slug-URL, geocoding via PDOK), elke studio ruimtes (`Room`, type opname of mix-master, min. 5 foto's). Ruimtestatus (`RoomStatus`): `concept` → `in_review` → `live` (of `afgekeurd`), plus `vakantie`. Live zetten kan pas als de verhuurder Stripe-uitbetalingen heeft geactiveerd.
- **Beschikbaarheid:** weekschema (`RoomHour`), uitzonderingen en blokkades (`RoomException`, `ExceptionType`), vakantiemodus, iCal-export. Geen agenda-sync (BESLISSING 6, grootste risico).
- **Boeking (`BookingStatus`):** `pending_payment` (slot 15 min gereserveerd) → `pending_confirmation` (verhuurder heeft 24 uur, herinnering na 12 uur, anders auto-annulering met refund) → `confirmed` → `completed`; zijpaden `declined`, `cancelled`, `expired`, `disputed` ("Meld een probleem" met bewijsfoto's, houdt de uitbetaling vast). Ook nacht- en meerdaagse boekingen. Verzetten: 1 keer, tot 48 uur vooraf.
- **Geld, altijd in centen** (`*_cents`): huur (`rent_cents`), optioneel engineer, servicekosten (`service_fee_cents`, percentage uit `config('studio.service_fee_percent')`, nu 9%, betaald door de artiest), btw, totaal. De verhuurder krijgt 100% van zijn uurtarief. Annuleringsstaffel 100/50/0% over de huur; servicekosten en btw gaan bij een refund helemaal terug (`Booking::refundAmountCents`). Uitbetaling van de huur via een Stripe-transfer op starttijd + 24 uur.
- **Facturen:** per betaalde boeking een huurfactuur namens de verhuurder (21% btw, of een huurbevestiging zonder btw bij niet-btw-plichtigen) en een servicekostenfactuur van StudioMatch, plus creditnota's; PDF via dompdf ([Support/Invoices](app/Support/Invoices.php)). Moneybird kan later.

## Code

- **Laravel 13, PHP 8.4**, MySQL (`studiomatch`, via Laragon op `http://studiomatch.test`; `.env.example` staat nog op sqlite). Geen Livewire/Inertia.
- **Frontend:** Blade-components ([resources/views/components](resources/views/components): `layout`, `dashboard-layout`, `artist-layout`, `host-layout`, `admin-layout`, `studio-card`, `studio-map`, ...) + Tailwind CSS 4 + Vite 8. JavaScript is gewone JS in één bestand, [resources/js/app.js](resources/js/app.js) (dropdowns, sliders, modals, kaart via Leaflet, sorteren via SortableJS); er is geen Alpine. Iconen: Font Awesome lokaal in `public/fontawesome/` (daarom staan er zoveel bestanden in `public/`).
- **Huisstijl:** Ruby Red `#AD0924` (accenten, CTA's), Prussian Blue `#101529` (primair, donkere vlakken), Charcoal Blue `#383E46` (secundair), wit. Tokens in [resources/css/app.css](resources/css/app.css) (`bg-ruby-red`, `text-prussian-blue`, ...). Font Inter via Bunny Fonts. Logo's in `public/logos/`.
- **Twee talen:** NL (standaard) en EN via `lang/nl` en `lang/en`, taal via [SetLocale](app/Http/Middleware/SetLocale.php). Elke nieuwe UI-tekst komt in beide talen in hetzelfde langbestand; nooit tekst hard in een view. Teksten die verhuurders zelf invullen worden niet vertaald.
- **Ondersteuning in `app/Support`:** `StripeService` (Checkout, Connect Express, refunds, transfers; zonder keys simulatiemodus), `Invoices`, `Geocoder` (PDOK), `ImageProcessor`, `Hours`, `RichText`, `MailDelivery`, `AccountAnonymiser` (AVG-verwijdering).
- **Mails:** alles via notifications in `app/Notifications` (de mailmatrix uit scope §2.10). Zonder Mailgun loggen ze naar `storage/logs/laravel.log`.
- **Automatisering:** `bookings:maintain` elke 5 minuten (verlopen blokkades, herinneringen, auto-annulering, sessies afronden, uitbetalen). De queue draait ook via de scheduler (`queue:work --stop-when-empty`), dus er is geen aparte worker nodig, wel een scheduler (`schedule:work` lokaal, cron live). Verder: `studios:geocode`, `stripe:check`, `mail:check`, `legal:import` (juridische teksten, met [scripts/legal_pdf.py](scripts/legal_pdf.py), `PYTHON_BIN`).
- **Stripe:** webhook op `POST /stripe/webhook` ([StripeWebhookController](app/Http/Controllers/StripeWebhookController.php)), testmode. Formulieren met reCAPTCHA (`RECAPTCHA_*`) en throttles op contact en auth.

## Mobiele app (Capacitor 8, iOS en Android)

Dezelfde opzet als RenovionApp (zustermap): **eigen schermen in de app, gegevens van de server.** Bouwen en uitrollen: [mobile/README.md](mobile/README.md).

- **Schermen** in [mobile/app](mobile/app) (Alpine + Tailwind, dezelfde tokens uit `resources/css/app.css`, Inter uit `@fontsource/inter`), gebouwd met `npm run app:build` ([vite.app.config.js](vite.app.config.js)) naar `mobile/www` (in .gitignore). Fase 1: inloggen, artiest "Mijn boekingen" + detail en studio's zoeken, verhuurder aanvragen (accepteren/weigeren) en agenda, account (taal, meer-menu, uitloggen). De beheerder heeft alles in de app (`api/app/beheer/*`, [Api\App\AdminController](app/Http/Controllers/Api/App/AdminController.php)): onderbalk Overzicht, Tickets (teller, afhandelen in een venster onderin: terugbetaling 0-100% en toelichting, of een reactie aan de verhuurder), Wachtrij (teller; ruimte beoordelen op `#/ruimte/{id}`: live zetten of afwijzen met reden), Boekingen (filter op status, status wijzigen) en Account met Gebruikers, Omzet en Blog. Gegevens via [AdminDesk](app/Support/AdminDesk.php), regels via de acties [HandleTicket](app/Actions/HandleTicket.php), [ReviewRoom](app/Actions/ReviewRoom.php) en [ChangeBookingStatus](app/Actions/ChangeBookingStatus.php); de website gebruikt dezelfde. Alleen blogartikelen schrijven (de editor) en de CSV-exports blijven serverpagina's. **Boeken zit in de app** (artiest): studio (`#/studio/{id}`), kies een moment (`#/boeken/{id}`: per uur of per hele dag, engineer, prijs vooraf berekend zoals de server), controleren (`#/afrekenen/{id}`: factuurgegevens, adres als dat ontbreekt, huisregels en akkoord), betalen (`#/betalen/{id}`, met aftellen; zonder Stripe rondt de app de demo-betaling af, met Stripe opent de betaalpagina als serverpagina en komt via `InApp::toApp` terug, `allowNavigation` kent Stripe) en verzetten (`#/verzetten/{id}`); annuleren vraagt eerst hoeveel je terugkrijgt. Endpoints in [Api\App\BookingController](app/Http/Controllers/Api/App/BookingController.php), regels gedeeld met de website via [BookRoom](app/Actions/BookRoom.php) en [ChangeArtistBooking](app/Actions/ChangeArtistBooking.php). Het gekozen moment staat tot het afrekenen in `sm-draft`. Opent een artiest in de app toch de studiopagina, het boekformulier of verzetten van de website, dan gaat hij naar het scherm in de app. Problemen melden blijft een serverpagina (foto's uploaden). Detailschermen staan in `DETAIL_SCREENS` en `PARENT_SCREENS` (main.js, `:id` = hetzelfde nummer), de tab die oplicht in `TAB_OF`: kop en terugknop van Android gaan naar het scherm erboven; vensters onderin via `sheet()` (sluiten met de terugknop). **Limieten in api/app:** een naamloze `throttle:N,1` deelt één teller per gebruiker met alle andere limieten (ook de 120 van de groep), dus een strengere limiet krijgt een eigen derde waarde (`throttle:10,1,app-boeken`). **Terug naar de app vanaf de server** nooit met een redirect naar `https://localhost` (de webview van Android stuurt die het netwerk op, dan staat er "Geen verbinding"), maar met `InApp::toApp('#/scherm')`, een pagina die zelf navigeert; foutpagina's in de app wijzen naar `app.back` (`?scherm=studios` kan ook).
- **API** `api/app/*` ([routes/api.php](routes/api.php), `Api\App\*`, payloads in [AppPayload](app/Support/AppPayload.php)): Sanctum-token per telefoon, vervalt na 60 dagen niet gebruiken (AppServiceProvider). Rollen strikt gescheiden met `app.role:...` ([EnsureAppRole](app/Http/Middleware/EnsureAppRole.php), ook geen uitzondering voor de admin). CORS alleen voor de app zelf (`SessionController::APP_ORIGINS`: `https://localhost`, `http://localhost`, `capacitor://localhost`). Bedragen in centen, foto's als volledig adres op de server die de app aanspreekt.
- **Zelfde regels als de website:** accepteren en weigeren via [RespondToBookingRequest](app/Actions/RespondToBookingRequest.php), boekingen van de artiest via `ArtistBookings`, agenda via `HostAgenda`. Nieuwe logica die website en app delen, hoort in zo'n gedeelde klasse, niet in een controller.
- **Teksten:** alles in `lang/{nl,en}/app.php`. Het deel `ui` haalt de app op via `api/app/teksten` (vóór het inloggen, taal uit `?locale` of de telefoon) en in `api/app/ik`; `php artisan app:texts` zet het bij elke build ook in de app (`mobile/app/texts.json`) voor de eerste start zonder verbinding. Nooit tekst hard in `mobile/app`.
- **Menu op één plek:** [AppMenu](app/Support/AppMenu.php) bepaalt per rol de tabs (schermen in de app) en de links (serverpagina's). `AppMenu::SCREENS` en `SCREEN_PATHS` in [main.js](mobile/app/main.js) zeggen welke serverpaden een eigen scherm hebben. Een nieuw scherm: endpoint + payload + test, tab in AppMenu, scherm in `index.html`, `ROLE_SCREENS` en `preload()` in main.js.
- **Inloggen dat blijft:** token in localStorage én `@capacitor/preferences` (iOS kan de webview-opslag wissen); uitloggen wist token, bewaarde gegevens en de cookies van de websessie.
- **Offline:** elk scherm toont meteen het laatst geziene uit een cache per gebruiker (`sm-cache:{id}:{scherm}`) en ververst daarna; een balk zegt van wanneer de gegevens zijn; zonder verbinding elke 15 s opnieuw; grijze blokken alleen de allereerste keer. Bevestigen via een eigen venster (`$store.app.ask`), nooit `confirm()`.
- **Serverpagina's in de app:** eenmalige code (`POST api/app/webcode`, 1 minuut, één keer) en `GET app/sessie` logt de websessie in en onthoudt `session('app_bundle')`. [InApp](app/Support/InApp.php) (sessie óf user agent `StudioMatchApp`, want een 404 heeft geen sessie) en `@inapp`/`@unlessinapp` in Blade: in de app laten de layouts hun eigen navigatie weg (kop, mobiele kop en onderbalk van het dashboard, footer, cookiemelding) en de pagina ziet eruit als een scherm van de app: bovenaan [x-app-return](resources/views/components/app-return.blade.php), dezelfde navy kop als de app (terug naar de app, paginatitel, merk; op het dashboard neemt hij de h1 over, die dan alleen voor schermlezers blijft; een iPhone heeft geen terugknop), onderaan [x-app-tabbar](resources/views/components/app-tabbar.blade.php), de onderbalk van de app (tabs en tellers uit `AppMenu::for`/`counts`, de tab van de pagina via `AppMenu::tabFor`, een tab opent dat scherm in de app), en `.in-app` op `<html>` met [in-app.css](resources/css/in-app.css): grijze achtergrond, kaarten zonder rand met schaduw, knoppen `rounded-xl` en 44px, bevestigen en meldingen onderin, geen ruimte meer voor de verborgen websitekop. Zonder sessie wijst de kop naar `GET app/terug` (`app.back`), dat het adres van de app kent of raadt. Een nieuwe layout: `@inapp class="in-app" @endinapp` op `<html>`, `<x-app-return :title>` bovenaan, `<x-app-tabbar />` onderaan en de eigen navigatie in `@unlessinapp`; een nieuwe websitepagina volgt de stijl vanzelf als hij de gewone bouwstenen gebruikt (kaart `rounded-2xl border bg-white`, knop `rounded-full px-*`). Websitepagina's tekenen niet onder de statusbalk; die ruimte heeft de kleur van `android:windowBackground` (navy, styles.xml), zodat de witte iconen leesbaar blijven. **Geen verbinding:** `offline.html` alleen bij een echte verbindingsfout ([StudioMatchWebViewClient](android/app/src/main/java/nl/studiomatch/app/StudioMatchWebViewClient.java)); een 404 of 403 toont de foutpagina van de website. **Terugknop (Android)** zit native in [MainActivity](android/app/src/main/java/nl/studiomatch/app/MainActivity.java): op een websitepagina terug binnen hetzelfde bezoek, vanaf de eerste pagina naar het scherm in de app waar je vandaan kwam, en dan de geschiedenis wissen (anders landt terug later in een oude websitepagina). In de app eerst `window.smBack` in main.js (venster onderin sluiten, van een boeking naar de lijst), dan een scherm terug, anders de app naar de achtergrond. Geen `backButton`-listener in de app-JS: op serverpagina's is de Capacitor-brug er niet.
- **Kop van de app:** de naam van het scherm (`title` in de store, uit `ui.*.title`) en op een detailscherm een terugknop (`backTo`); geen paginakop meer in de inhoud. Tikvlakken minimaal 44px (`min-h-11`). Meldingen kort (de app heeft eigen korte teksten, niet de lange van de website), tik om weg te halen, weg bij een ander scherm.
- **Laravel herkent de app** aan user agent `StudioMatchApp` (capacitor.config.ts). App-id `nl.studiomatch.app`, icoon en splash via `npm run mobile:assets` (ook het witte statusbalkicoon `ic_stat_studiomatch`).
- **Pushmeldingen (Firebase, project `studio-match-app`):** nu alleen voor de beheerder, bij een nieuw ticket ([NewTicket](app/Notifications/NewTicket.php), los van de mails, verstuurd via `MailDelivery::send`). [PushChannel](app/Notifications/Channels/PushChannel.php) stuurt via [FirebaseMessaging](app/Services/FirebaseMessaging.php) (HTTP v1, eigen JWT) naar `device_tokens`; dode tokens gaan weg, zonder sleutel gebeurt er niets. Sleutel: `FIREBASE_CREDENTIALS` (lokaal `storage/app/private/firebase-credentials.json`, buiten Git; elke server die push stuurt heeft hem nodig). App: `@capacitor-firebase/messaging` en `android/app/google-services.json` (bevat een API-sleutel: **niet in Git**, staat in .gitignore; downloaden uit Firebase en lokaal neerzetten); `registerPush()` in main.js vraagt toestemming alleen voor `PUSH_ROLES`, meldt het token aan (`POST api/app/apparaten`), uitloggen stuurt `push_token` mee; tikken opent `data.url` via `go()` (Tickets), met de app open geen melding maar de teller en het scherm verversen (`sm-refresh`). Nieuwe soort: notificatie met `toPush()` en `PushChannel` in `via()`, rol in `PUSH_ROLES`. iOS nog niet gekoppeld (APNs-sleutel, `GoogleService-Info.plist`, alleen op een Mac).
- **Android bouwen:** met JDK 21 (`JAVA_HOME=D:\Android\jdk-21`); de Java van Android Studio is 25 en dan faalt Gradle met "Unsupported class file major version 69".
- **Tests:** [AppApiTest](tests/Feature/AppApiTest.php) (API), [AppWebPagesTest](tests/Feature/AppWebPagesTest.php) (websitepagina's in de app) en [PushNotificationTest](tests/Feature/PushNotificationTest.php).

## Werkwijze

- **Opstarten:** `composer run setup` (install, .env, key, migrate, npm build), dan `php artisan storage:link`, `php artisan db:seed` (demodata, idempotent) en `composer run dev` (server, queue, logs, Vite). Scheduler in een tweede terminal: `php artisan schedule:work`.
- **Testaccounts** (na seeden, wachtwoord `wachtwoord123`): `artiest@`, `verhuurder@`, `demo-verhuurder@` (met data) en `admin@studiomatch.test`.
- **Tests:** feature-tests in `tests/Feature` (boekflow, beschikbaarheid, facturen, Stripe, feedbackrondes, ...). Na elke wijziging de relevante tests draaien (`php artisan test --filter=...`), en bij nieuw gedrag een test toevoegen of bijwerken. Formatteren met `vendor/bin/pint --dirty`.
- **Styling:** Tailwind 4 maakt alleen classes die het in templates ziet; laat `npm run dev` draaien, of `npm run build`. Geen styling en geen dev-server? Verwijder een achtergebleven `public/hot`.
- **Mobiel eerst:** elke pagina eerst op telefoonbreedte controleren (geen zijwaarts scrollen, tikvlakken groot genoeg).
- **Niet in Git:** `.env`, `vendor`, `node_modules`, `public/build`. De feedback-PDF's zijn stukken van de klant: lezen, niet aanpassen.
- **Wacht op de klant** (zie README): Mailgun-gegevens, Stripe-webhooksecret, btw-bevestiging van de accountant, definitieve juridische teksten, BESLISSING 13 (blog). Bouw daar niet omheen zonder overleg.
